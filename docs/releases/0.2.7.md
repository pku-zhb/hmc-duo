# 0.2.7 source and owner acceptance

This iteration addresses owner reports from HMC 0.2.6 / Lite 0.1.7, paired with
Lite 0.1.8. Read-only phone diagnostics were collected without UI operation or
screenshots. Code, JVM checks and builds do not establish native visual acceptance.
The owner-facing checklist is updated in place in the existing rolling document.

## Confirmed source gaps and remedies

- **Direct full-AOD sampling:** the local sampler recognized only the awake mesh,
  although full-screen AOD draws a separate static wash. The wash's actual drawn
  generation now authorizes sampling in the same window; no continuous AOD mesh
  animation is enabled. Native recipe ownership remains unchanged.
- **Clock first frame:** direct sleep could omit the lyrics page's clock hold,
  and a new glyph's first valid outline returned before the collapse pose was
  reapplied. Sleep preparation and same-draw first-measure placement now precede
  native frame submission, including navigation entry. Visual flash removal is
  still an acceptance goal, not a measured claim.
- **Folded page controls:** card guards removed listeners from a newly obtained
  observer rather than the observer on which they were installed. Old callbacks
  could repeatedly replace a new card's button. Saved observer removal and
  ownership checks retire those callbacks. Explicit cycling uses the present
  attached/shown card, not the transient native top-card flag. A read-only sample
  reported 5,479 button creations/releases while lyrics already contained 36 lines;
  this supports investigating lifecycle churn, not a synchronized reproduction.
- **Lyric latency:** a locally drawn artwork backdrop still waited on an old
  remote wallpaper acknowledgment. The verified local generation now releases
  that gate without waiting up to 1.2 seconds; absent/provider-bound lyrics keep
  their actual availability and loading behavior.
- **Material relay:** rebinding cleared a scene profile even if the same native
  RenderNode had already accepted an identical recipe. A weak per-node successful
  commit cache survives that clearing; an unchanged return is accepted only if
  its values exactly match that node's prior successful commit. Unknown/rejected
  values never seed it. Native holder lineage and live window validation replace
  the old cached-card identity gate, allowing a new folded holder to be tracked
  before its first successful material write.
- **Inner alignment:** restoring only the OEM stack width in 0.2.6 left its axis
  different from Duo's clock/artwork axis. Both inner orientations now use their
  current Duo content frame, potentially wider than the OEM column as explicitly
  preferred by the owner. Vertical native stacking remains native.
- **Compact player:** normal background/layout changes alone did not update the
  native minimum and animated target. One compact plan now supplies those normal
  endpoints while keeping the native full-AOD shell. Native actual height drives
  the transition background; seek/time pixels are concealed before clipping and
  return during wake. Cancellation settles the owned transition through native
  media completion. 75–100% prioritizes inter-row spacing and scales header art
  toward 40dp, while preserving playback/seek controls and large-font safety.
  See [the height contract](../../design/PLAYER_HEIGHT.md).
- **Credits:** the behavioral reference uses concise user-facing wording; legally
  required copyright and license notices remain intact. HMC already contained its
  animated About and liquid navigation implementations; Lite's missing equivalent
  UI and fixed gray footer were repaired in Lite 0.1.8. The same HMC gray-footer
  report was not established by source review and remains a targeted visual check.

## Verification

The full HMC JVM suite passes 1,044 tests in 169 suites with zero failures, errors
or skips. Debug lint and builds pass. Final delivery uses a clean committed/pushed
source, optimized signed build and embedded-source/certificate/hash verification.
GPU sampling, first-frame clock visibility, clipping, transition timing and fold
interaction still require owner acceptance. This iteration does not install or
reload a phone scope without current explicit owner authorization.
