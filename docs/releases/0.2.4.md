# 0.2.4 owner acceptance

## Changes and confirmed causes

- The 0.2.3 edge renderer filtered an already-combined stack strip. A partially
  shelf-covered row therefore included its stationary neighbor. The replacement
  composes a mask into each moving native card and preserves native clip/Z order.
  Media headers declare their own translation method; it is now observed too.
  See [native-card edge ownership](../../design/NOTIFICATION_EDGE.md).
- Inner portrait was explicitly excluded by the compact-clock display predicate.
  It now permits the same three destinations while retaining visibility/layout guards.
- Native media glass sampled across the SystemUI window, behind the locally drawn
  artwork backdrop. The existing media background now uses local sampling during
  that backdrop session and restores the latest native sampler on release. Its
  glass recipe remains owned by the current material provider. See
  [local sampling](../../design/LOCAL_MEDIA_SAMPLING.md).
- Settings mixed artwork, rail geometry and initial content in one card, and hid
  existing prerequisite summaries. Separate groups/pages now expose the relevant
  controls, collapse inactive children and distinguish notes from interactive rows.
  Initial state is under lock-screen capsules; charging text is under interface
  cleanup. Media marquee labels, blur units and dial-code copying are corrected.
- Keeping the last lock screen could stop saving indefinitely after testing AMap.
  Its page-readiness flag remained armed with no current navigation card, yet that
  flag alone kept the temporary navigation session active and blocked normal
  checkpoints. Navigation priority now also requires the live navigation card.
  Removing that card releases the temporary session, restores its saved choices
  once and permits ordinary last-state saving again. The map readiness signal
  and the owner's settings are left intact.

## Host checks

The final Debug JVM suite passes: 1,008 tests in 164 suites, with no failures,
errors or skips, including four new navigation-liveness regressions. Debug lint
passes with existing non-blocking platform warnings. Resource identity
and UI references were checked across default, English and Chinese; stored keys
and bridge operations are unchanged. Final delivery uses a clean pushed source
revision with embedded identity, the existing signing certificate and the local
archive verifier. Native GPU appearance is not established by these checks.

## Focused device checks

1. Swipe notifications, player and live cards in both directions, including a
   notification only partly exposed above the shelf. Only the moving card should
   feather; native material and its stationary neighbor should remain intact.
2. In inner portrait, test navigation/artwork/lyrics with the date-row and status
   clock destinations. They should follow the selected setting.
3. With Lite owning music material and Duo's blurred artwork background enabled,
   check that music glass sees the current artwork, then native wallpaper after
   disabling that background. Include dismissal and the next track/session.
4. Check settings in Chinese/English: switches reveal their own children; keeping
   the previous lock screen hides manual defaults without clearing them; right
   rail/reflow govern notification floor; copy the launcher dial code and paste it.
5. With navigation stopped, enable keeping the last lock screen, change expanded
   content/music page, unlock and lock again. Repeat in portrait and inner
   landscape. A real navigation card should still take temporary priority;
   ending navigation must restore the prior layout and resume remembering changes.

No phone GUI, screenshots, installation, scope restart or reboot is part of this
source iteration. The owner accepted ordinary notification feathering, reduced
tuning jank, volume behavior and the main navigation path in the previous round;
they are not a repeated full regression list. The small desktop-to-screen-off
status-cluster overlap is explicitly deferred. Compatibility repair is unchanged.
