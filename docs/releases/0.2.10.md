# 0.2.10 foreground-backed artwork sampling

Includes [0.2.9](0.2.9.md) and pairs with Lite 0.1.9.

Cross-testing an instrumental track found a second path to empty artwork sampling:
explicit lyrics selection correctly cleared notification compaction, but no lyric
content existed and the cover remained compact. Background eligibility now uses
the shared normalized foreground state. A real expanded artwork/combined page,
available lyrics or companion content, and the explicit player-only presentation
retain their backgrounds; an empty compact lyrics page releases them. No delay,
retry or additional suppression flag is introduced.

Posture testing also found a pre-cropped landscape background being stretched onto
the outer portrait window. Local composition now has an immutable source/window/
geometry/mode identity and rebuilds from retained original artwork off the UI
thread. Stale completion is rejected. Desired and actually drawn composition keys
remain distinct, so same-source outgoing pixels can bridge a rebuild without
being reported as a newly drawn geometry or temporarily sampling native wallpaper.

Paused lyrics previously received a varying vsync-to-dispatch correction intended
for running playback. At a lyric boundary, a fixed native position of 1530 ms
became 1523–1529 ms and repeatedly restarted focus and scrolling. Paused playback
now uses the exact native position; seek, rate and playback state come from one
snapshot. Existing transitions settle normally rather than being cut off.

Host tests, optimized APK provenance and installed scenario results are recorded
separately. See the existing rolling acceptance document for device observations
and the remaining visual checks.
