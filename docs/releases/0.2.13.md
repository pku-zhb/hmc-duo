# 0.2.13 native AOD progress and inner-screen layout

Includes [0.2.12](0.2.12.md) and pairs with HC Lite 0.1.10. Existing APKs,
upgrade identity, settings and native security/authentication are retained.

## Causes and changes

- Inner single-page layout explicitly expanded its safe content frame back to
  the whole window. Owned visuals now retain the rail-safe frame and native-width
  cards move onto that same axis. The combined landscape page divides usable
  space equally, with a narrower player matching the artwork width. Native
  vertical stack/height ownership is preserved for both 75/100 presets.
- Inner date placement inherited the outer camera restriction. Inner portrait
  and landscape now use a 24dp top line, while outer-screen policy is unchanged.
- The global full-AOD manager could be enabled while the native current inner
  display gate was false. HMC now reads the display-specific answer. An explicit
  default-off experimental switch can extend only that inner gate, preserving
  native master, wallpaper and clock-style restrictions. Unknown native contracts
  retain their own behavior; no invisible root or power state is forced.
- Separate AOD timers and ordering let the clock, artwork and lyric geometry use
  different progress or one-frame-old poses. Presentation follows one native
  absolute progress snapshot, and geometry synchronizes after clock pose commit.
  Lyrics carry geometry movement separately from focus easing.
- Outgoing backdrop alpha could expire before actual handoff, including a second
  sleep after wake. Retained committed pixels now stay opaque until the incoming
  renderer is ready. Compact seek opacity follows available actual height in
  both directions without taking native shell-height ownership.

See [native progress](../../design/AOD_TRANSITION.md),
[inner AOD eligibility](../../design/INNER_SCREEN_AOD.md) and the shared
`FoldMusicLayout` / `RailContentFrame` geometry policies.

## Validation boundary

The complete JVM suite passes 1,220 tests in 187 suites, with no failures,
errors or skips. Debug lint and `git diff --check` pass. The final APK is assembled
separately from clean committed, pushed source with the existing upgrade identity.

Host policy tests do not prove every visual frame or actual display power state.
Native callback registration, inner panel visibility, measured player width,
sleep/wake and restoration are checked separately on the phone. Final transition
smoothness and contrast need human observation where background state is
insufficient. The existing rolling acceptance document records the actual
installed versions and latest device outcomes; no complete regression round is
requested solely because a new package is built.
