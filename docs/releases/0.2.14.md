# 0.2.14 AOD plugin display eligibility

Includes [0.2.13](0.2.13.md), with HC Lite 0.1.10 unchanged.

The 0.2.13 device check confirmed the inner native keyguard root participates in
full-AOD rendering after opt-in, but the physical display remained OFF. The AOD
plugin independently repeats the inner-display support check. The outer-display
reference remained ON with the same configuration, so a visible view tree alone
was insufficient evidence.

The experimental setting now extends both native display eligibility gates.
The plugin receives a single watched boolean choice from SystemUI and keeps its
native masters, clock-style, scheduling, brightness and display power paths.
The live plugin loader is observed through its typed connection event; there is
no global class-loader callback, forced root alpha or direct power-state write.
See [inner AOD ownership](../../design/INNER_SCREEN_AOD.md) for the exact contracts
and separate host/device validation requirements.

The complete 1,220-test JVM suite, Debug lint and main compilation pass without
failures, errors or skips. The signed package is assembled from clean committed,
pushed source; actual inner display state remains a separate device check.

On the physical inner display, that device check passes: enabling the setting
produces `DOZE`, visible native keyguard parents and committed replacement time;
the inactive outer display stays OFF. Disabling restores both native gates, the
shared choice and native inner OFF behavior. Lyric/combined pages and interrupted
sleep/wake settle at valid committed poses with exact native endpoints. The
current clock style is verified; other template eligibility remains native.
No screenshots or full reboot were used. This is not a claim of complete visual
smoothness or measured power behavior. The artifact remains pinned to its
archived source commit; this subsequent documentation commit changes no APK.
