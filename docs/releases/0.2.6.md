# 0.2.6 source and owner acceptance

This iteration follows the owner's 0.2.5 feedback. It is developed and checked
entirely on the host: no phone connection, screenshots, installation, live tuning
or scope restart. Previously accepted pull-down backgrounds and last-lockscreen
state retention are not a repeated acceptance list.

## Confirmed causes and changes

- **Artwork sampling:** detach and leaving keyguard retired the only accepted
  holder binding and its attach listener. If the OEM reused that holder without
  another material effect, it never reacquired local sampling. The binding now
  survives temporary absence weakly, restores current native flags on suspension
  and revalidates the source on attach. The existing final material recipe is
  unchanged. See [local sampling](../../design/LOCAL_MEDIA_SAMPLING.md).
- **Lyrics:** same-track entry could find an available cache but leave the display
  list empty after artwork/BPM presentation cleared it. Explicit entry restores
  parsed lines first; a completed miss can retry at most once per 15 seconds on
  a later entry. In-flight requests are not duplicated, and worker errors finish
  loading promptly. Real lyricless tracks remain unavailable. See
  [lyric recovery](../../design/LYRIC_PAGE_RECOVERY.md).
- **Navigation AOD:** after a manual close, navigation layout and its clock hold
  arrived after the OEM captured the large-clock pose. Full-screen AOD now
  commits the live navigation layout and selected clock pose before capture,
  including the bounded remote-page return path. Stale readiness alone never
  gains ownership. See [entry ordering](../../design/LOCKSCREEN_ENTRY.md).
- **Predictable music reopening:** taps and upward expansion used different
  forced pages. Both now use the configured expansion page. Outer and inner
  portrait share player/artwork/lyrics; inner landscape independently retains
  its fourth combined page. Last-state restoration still controls initial entry.
- **Native inner widths and swipe timing:** inner portrait and landscape no
  longer acquire Duo's fixed native-card frame. Original notification/media/live
  widths remain native; Duo's own artwork/lyrics layout keeps its own rooms.
  A fresh native effect during a swipe now receives its feather in that same
  commit, rather than waiting for the next draw. Partly covered cards keep their
  already accepted native clip/Z order.
- **Adjustable height:** both display profiles default to the native height.
  85–100% only compresses verified vertical gaps, retaining artwork, action and
  seek-touch dimensions; tight native variants retain their safe minimum. See
  [height contracts](../../design/PLAYER_HEIGHT.md).
- **Settings and About:** expansion choices stay editable independently of
  initial collapse/keep-last settings; height has portrait/landscape controls.
  Functional pages use generic module names. About includes the companion-app
  link, acknowledgements and complete offline legal notices.

## Verification boundary

Focused tests cover holder reuse, lyric entry/retry, navigation pose ordering,
shared portrait/independent landscape choices, native width ownership, same-frame
feathering, height safety and backup normalization. The full JVM suite
passes 1,035 tests in 168 suites with zero failures/errors/skips, and Debug lint
passes. Final clean-source package/source/signature/hash checks use the archive
workflow. Native visual behavior, GPU sampling,
gesture timing and font/layout comfort remain owner acceptance.
