# 0.2.11 replacement-time acquisition during direct AOD entry

Includes [0.2.10](0.2.10.md) and pairs with Lite 0.1.9.

Fresh-session device testing reproduced a clock failure on desktop-to-full-AOD
entry: the lyrics backdrop was correctly committed, but the native clock remained
visible and the status-cluster time stayed at zero alpha until wake. The saved
lyric page was correct. An earlier test with an expired native media card did not
exercise this scene and is not acceptance evidence for it.

The initial AOD preparation could observe incomplete date geometry or an unavailable
replacement-time resource. It then latched a held pose with a zero replacement
target. Only the lit phase re-evaluated that target. Replacement intent, resource
readiness and actual visibility now have distinct roles in the same scene commit;
late readiness can acquire within full AOD. Native and replacement visibility are
committed together. No delay or retry is added.

Host checks and installed device results remain separate. The existing rolling
acceptance document records the final evidence and any visual limitations.
